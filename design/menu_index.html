    • 一级菜单划分明确
    缺点
    • 跨阶段动作（如报损）需放到具体环节，可能不直观

    2 操作 vs 配置

    把"动"的（建单/操作）和"静"的（查询/配置）分开。员工 80% 时间在前者。
    📌 适合：日常操作员居多、希望"常用的放最上面"
    优点
    • 常用最快触达
    • 权限分配清晰
    缺点
    • "操作"和"查询"边界有时模糊（如盘点）

    3 三支柱（动作-资源-洞察）

    借鉴产品设计三分法：操作（做什么）/ 资源（看什么）/ 洞察（学什么）。
    📌 适合：管理视角、汇报时菜单结构本身就是"故事"
    优点
    • 顶层抽象有美感
    • 未来扩展空间大
    缺点
    • 抽象层级高，新员工要学

    4 全扁平化

    完全没有一级菜单分组，所有功能直接平铺在侧栏。一次点击直达。

    优点
    • 0 学习成本
    • 1 次点击直达
    缺点
    • 菜单 >12 项时显得拥挤
    • 无法逻辑分组

    6 角色视角

    按"谁会用"做分组：现场工人 / 仓库浏览者 / 老板视角。让登录后第一眼找到自己。
    📌 适合：用户角色差异大、人员流动频繁需快速适应
    优点
    • 角色感强
    • 权限映射直接
    缺点
    • 同一功能可能跨角色，需取舍归属

    🎯 选型建议

    • 如果贵公司 业务流程很标准化（货怎么进、怎么存、怎么出），推荐 方案 1（业务流程导向） — 符合自然心智
    • 如果 员工日常 80% 时间都在登记单据，推荐 方案 2（操作 vs 配置） — 常用的最快触达
    • 如果 用户喜欢"产品感"，追求极简结构，推荐 方案 3（三支柱） — 顶层最美
    • 如果 菜单总数 ≤ 13 项，希望新人零学习成本，推荐 方案 4（全扁平） — 一击直达
    • 如果 未来还会加 5-10 个新菜单，推荐 方案 5（细粒度分组） — 留有扩展空间
    • 如果 不同岗位差异大、希望登录后立刻找到自己的活，推荐 方案 6（角色视角） — 角色感最强
