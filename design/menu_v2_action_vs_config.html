设计思路

把所有菜单按"是否产生数据变化"划分两类：

🔄 动 — 日常操作

  • 建单（入库/出库/调拨）
  • 登记动作（报损/盘点）
  • 都会修改库存数据
  • 员工 80% 时间在这里

👀 静 — 查询分析

  • 看现状（库存/流水）
  • 看趋势（报表/预测）
  • 都是只读，不改数据
  • 经理 / 老板看的多

下方两组「数据维护」+「系统」是"低频但重要"的配置项，平时不动，初始化或调整人员时才进。

菜单映射

菜单归属性质
入库 / 出库 / 调拨 / 报损 / 盘点日常操作动 — 会改库存数据
库存查询 / 流水 / 报表 / 预测查询分析静 — 只读
商品 / 供应商数据维护低频改 — 主数据
仓库 / 库位 / 存储区数据维护极低频 — 基础设施
系统全部系统仅 admin

为什么这么改

对操作员的好处：登录后第一眼就看到所有「我能操作」的菜单。"日常操作"组永远显眼，不会和"配置项"混淆。

对管理员的好处：进入"查询分析"组就是"看数据时间"，不会误点到会写数据的菜单。

权限分配简单：操作员 = 只勾"日常操作 + 查询"；经理 = 全勾；admin 自动看全部。
