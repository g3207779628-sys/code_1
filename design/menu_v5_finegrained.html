设计思路

把现状的"业务（2 项）+ 仓库管理（9 项）+ 商品管理（2 项）+ 系统（5 项）"重新切成 8 个语义精确的小组，每组只有 1-3 个子菜单。

核心区别于方案 1（业务流程）：本方案不按业务阶段，而是按菜单本身的"性质"分组。

8 个分组的命名与归属

分组名包含菜单分组理由
看板 工作台 / 待审批中心 登录即看，覆盖所有人
物流操作 入库 / 出库 / 调拨 所有"货物位置变化"的动作 — 物在动
库存浏览 库存查询 / 流水 "看现在 + 看历史" — 只读
库存调整 报损 / 盘点 "修正账实差异" — 与物流不同，是账上的修正
数据分析 报表 / 预测 汇总洞察，老板视角
商品资料 商品 / 供应商 业务侧的基础数据
仓库设施 仓库 / 库位 / 存储区 物理/逻辑空间的基础数据
系统 用户/预设/通知/备份/密码 仅 admin 维护

为什么把"物流操作"和"库存调整"分开

这是本方案最关键的设计点。"调拨"和"盘点"看起来都改库存，但本质不同：

  • 物流操作 = 货真的在动（A 库位 → B 库位），物理移动
  • 库存调整 = 货没动，但账上的数字要改（发现少了一件 → 报损；盘点发现多了 → 调账）

这两类操作的审批流程、使用频率、谁能做都不一样。把它们分开后，员工去找菜单时一眼就知道走哪条路。

扩展性

每个分组都还有"空位"。未来加新菜单时归属直接：

  • 加"退货管理" → 物流操作组
  • 加"批次追溯" → 库存浏览组
  • 加"客户对账单" → 数据分析组
  • 加"客户" → 商品资料组（改名"主数据"）

这种"每组留位"的设计，让 1-2 年内不需要重新组织菜单。
