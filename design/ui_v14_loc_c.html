数据库 schema（与现状一致）

CREATE TABLE location ( id INTEGER PRIMARY KEY, warehouse_id INTEGER REFERENCES warehouse(id), code TEXT NOT NULL, -- 用户自己用约定 "1栋-2层-A01" zone_type TEXT ); -- 优点：什么都不改 -- 缺点：查询"1栋总在仓量" 用 LIKE 不严谨 SELECT SUM(inv.on_hand) FROM inventory inv JOIN location l ON l.id=inv.location_id WHERE l.code LIKE '%1栋%'; -- 漏掉 "1号楼-..." 这种
★ 优点
· 实装零工作量（甚至不用动一行代码）
· 命名最灵活，跨仓 / 临时区 / 特殊场景都好处理
· 适合**仓库结构简单**的场景：1 个仓库 / 1 栋楼 / 几个货架
✗ 缺点
· 治理靠人，"1栋 / 1号楼 / 1-栋 / 主楼" 几种写法同时存在导致查询漏数
· 不能 GROUP BY 楼栋（只能 LIKE 模糊查）
· 将来真有 5+ 栋楼时，从 C 升级 A 数据清洗代价大
· 部分用户可能根本不写楼栋号，靠记忆识别"A-01 是 1 楼"
