v17 库存 / 物品查询页 · 3 个方案对比

当前库存查询和物品查询都只有 1-2 个筛选框（搜索 + 简单 state）。v16 数据建模完毕后，需要按 9 + 7 个维度筛选。本批 3 个方案展示如何容纳这么多筛选项，每个方案配套库存查询 + 物品查询两个 mockup。
// 筛选维度清单
库存查询（9 项）
  • 楼栋号 / 楼层 / 库位 → location 表字段
  • 仓库编号 → warehouse 表（v15 字段保留）
  • 分配部门 / 使用部门 / 类型 / 责任人 → location FK
  • 是否分配 → 库位是否归属（有 alloc_dept_id 即"已分配"）
物品查询（7 项）
  • 品牌（brand）/ 用途（usage_purpose）→ sku 文本字段
  • 物品类别 / 物品大类 → sku FK
  • 物资管理方 / 物资所属单位 → sku FK
  • 是否在合同内（in_contract）→ sku 0/1 字段

推荐 P2 顶部折叠。理由：① 你的团队 20 人日常多数情况只用 2-3 个筛选（按仓库 / 按类型），P2 顶部一行就够；② 真要复杂查询时点"+ 更多筛选"展开 5 个 advanced，体验渐进；③ 主表格区 100% 宽度，铺满好看；④ 移动端友好。 如果是数据分析师每天用多条件 → 选 P1 侧栏；如果想按场景切换查询模式 → 选 P3 Tab。
